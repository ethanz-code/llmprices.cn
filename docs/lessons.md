## 6. 工程习惯（踩出来的规矩）

- 列表接口里「只有详情弹窗才用得到」的胖字段会跟着每一份列表下发：`/api/feed` 一次 1.30 MB，其中整份公告正文 HTML 625 KB、价格事件的采集溯源 metadata（网络证据/计价口径/启用分组）484 KB，而列表侧只渲染摘要与分组标签——首页 657 KB、历史页 2.78 MB 全被它顶起来。排查口径：按字段累计字节排序，比读代码快 | 列表只下发渲染用得上的字段：正文换成与前端同口径的摘要（`llm_price_monitor/feed_page.py` 的 `notice_excerpt`），metadata 走白名单 `EVENT_METADATA_KEYS`；全文/明细另开按需端点（`GET /api/notice/event`），浏览器侧经 `web/app/api/notice-event` 转发取（带内网令牌，不动生产的读接口封锁）| 本次提交；feed_page.py；web/app/api/notice-event/route.ts；实测 1.30 MB → 284 KB |
- 后端新增 GET 路由必须显式归类，漏了会被守卫测试抓住：`tests/test_webapi.py::test_admin_get_routes_denied_to_anonymous_by_default` 枚举全部 `GET /api` 路由，凡不在 `public_gets` 里的都断言匿名访问返回 401（新加的 `/api/notice/event` 匿名拿到 422，说明既没进公开清单也没被门禁挡住）| 新加 GET 端点后同步登记：公开读进测试的 `public_gets`，管理员专属进 `app.py` 的 `admin_get_paths`/`admin_get_prefixes`；只想让服务端转发调用（浏览器拿不到）的端点归前者，封锁交给 `public_get_paths` 决定 | 2026-10-13 实测；tests/test_webapi.py 的 `public_gets` |
- 改纯函数口径（如 `calcCost` 的缓存档缺价回落）必须同一提交改掉钉旧口径的断言：只改实现不改测试，工作区就停在「实现已改、断言没跟」的自验红状态，下一个跑测试的人得先分辨这是新漏洞还是旧钉子。收尾必跑全量（后端 `uv run pytest tests -q` + 前端 `tsc --noEmit` 与 `vitest run`），红了不许收。
- 静默兜底是坑：吞异常、回落默认值会掩盖真问题 → 删静默兜底、吞异常点补日志（提交 843bcd9 / f2346a1）。
- 默认路径不藏重活：默认动作（刷新/保存/打开页面）要秒级返回，逐个请求几千候选这类重活只放显式入口（CLI/单独按钮）；进度条救不了语义错误的默认行为，用户点破「我只是要清单」后先改语义再谈体验。
- 提交信息中文讲清"改了什么、为什么"，不写 `fix`/`update` 空话。
- 测试用 HTTPX mock transport / 进程内替身，不请求真实站点；改口径前先跑全量。
- 测试里经 create_app 放行任何 >0 的调度间隔（含按键回填补出来的新键）会被调度线程首轮 `_run_due` 真提交并执行——真实外网请求（discovery 实测打了 zuiquanapi 4339 条，还泄漏进后续测试的断言）；这类场景直测纯函数（如 `_ensure_schedule_defaults`），别拉起整个应用。
- 新增一类定时任务（settings.schedule 补新键）上线即跑一轮：_ensure_schedule_defaults 回填后 schedule_state 里没有该键，首轮 _run_due 视为到期当场提交——dev 热加载站点截图代码时全站真拍了一轮（2026-10-12），随后代码再热重载又把它打断（「服务重启，任务中断」，已知坑）。上线新调度项前想清楚首轮全量采集的影响；被打断的截图任务直接重跑即可，无副作用。站点人气同款（2026-10-14）：热加载后首轮当场提交、再改码又被打断；注意被打断的任务 `schedule_state` 已记提交时间，定时要等一个完整间隔才会再来，验证/补数据直接手动跑一轮任务体。
- 文案说人话、给下一步动作，不出现"接口/字段/渲染"这类实现词；提示/告示类别写成书面腔（"建议…""请自行判断""不构成…"），≤ 3 句、每句给动作或判断，写法样本见 `web/lib/copy.ts` 的 `risk` 块（2026-10-13 用户两轮纠正后定稿）。
- 并行会话同仓干活时，共享大文件（如 globals.css）的未提交改动会被对方的主题提交卷走：主题无关的布局改动改完即小步提交，别攒。
- 密钥回显方案终局是明文（2026-10-08）：设置接口 GET/PUT 直接回明文，前端 SecretInput 普通 password+眼睛本地显隐。此前的掩码/reveal/保长掩码机制全部拆除——给单管理员自托管后台加「完整密钥不出后端」这类安全硬化前先过问用户，交互摩擦会把它顶回来（连续三轮返工：掩码→按需 reveal→保长掩码→明文）。仍然有效的一条：新加管理类 GET 端点必须同步加进 app.py 的 admin_get_paths 白名单，漏加就是匿名可读。
- git 历史批量归并只有 rev-list 机器清单是事实源：手抄提交清单必漏（74536f6 漏抄、并行会话中途新插的 1b75f27 都栽过）；hash 集合对比前先 rev-parse 规范化，重放分组必须是拓扑连续段。流程铁三角：先 branch 留底 → 重放后 `git diff backup` 必须为空 → 强推必用 `--force-with-lease`（2026-10-09 全量 224→42 实证，旧历史 backup/pre-squash-20261009）。
