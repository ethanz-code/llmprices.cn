# 页面对照核查（采集值 vs 站点页面）

> 用途：配新站或对价格标准存疑时，用站点自己的页面验证库里的价格和公告是否与用户看到的一致。接口 JSON 和源码注释都可能误导——**页面渲染值是唯一事实源**（2026-10-12 2btocken 实证：plaza 接口 pricing 未含组倍率，源码注释却写「实收标准已含倍率」，采到的价是页面实付价的 4 倍）。

## 价格源优先级

1. **模型列表页优先**（new-api 系 `/pricing`、自研站的模型列表/价目表）：页面有模型列表就以它为准。
2. **Model Plaza / 模型广场只在没有模型列表时后备**（sub2api 系部分部署只有广场没有列表，如 2btocken）。
3. 两者都没有、只有渠道倍率 → 走渠道倍率合成（见 sites.md），标 candidate。

## 核查步骤（真实浏览器 + 登录态；工具按当前环境选，见 [sites.md](sites.md)「工具栈」表）

1. 打开站点价格页——公开页直接开（ZCode 用 IAB、WorkBuddy 用 `agent-browser`）；登录限制站先注入登录态（sub2api 系 localStorage 四键、new-api 系 session Cookie，见 lessons.md §3；WorkBuddy 无内嵌 cookie 库可拷，从用户系统浏览器手抄或 `agent-browser` 会话内登录，见 sites.md SOP 步骤 4）。
2. 看页面网络请求（ZCode：performance 资源列表或 DevTools 网络面板；WorkBuddy：`agent-browser snapshot` 看渲染结果 + `curl` 候选接口族），确认页面实际打的价格接口与站点配置的 `network.url` 是同一个；顺带扫一眼有没有漏配的渠道状态/公告接口。
3. 挑 1-2 个监控清单内模型，读页面显示的输入/输出价与币种标注，和库里 `latest` 对应记录对账：
   - 页面价 = 库里价：通过。
   - 差一个组倍率/充值汇率倍数：页面展示的是基准价、计费才乘系数（HeyRoute 型：页面 $12 = 基准，库里 ¥157.68 = $12×组倍率 1.8×充值汇率 7.3）——在 notes 里写明语义即可，不算错。
   - 对不上且说不清倍数：采集标准有误，先修解析器再重采，别在配置里打补丁。
   - **UI 登录限制但 `/api/pricing` 匿名可读的站**（2026-10-14 新增站多见：前台 `/pricing` 跳 `/login`）：页面渲染值拿不到时改做**载荷级逐组对拍**——拉 `/api/pricing` + `/api/status`，按 `model_ratio × (1e6/quota_per_unit) × price × group_ratio`（输出再乘 `completion_ratio`）对每个 `enable_groups` 逐组算，与库内逐组行比对。样本要挑多组、多种模型，别只对一个模型；「公式有值、库内无行」的组先查 `above_official`（超官价被产品决策丢弃属预期，2026-10-14 xi-ai/kfcv50 实证）。
4. 公告：打开公告入口（弹窗/公告页），正文与 `notice_records` 最新版本对照；页面有公告而库里空，先查公告链路 401（认证没配）与正文字段名（01tree description 键教训）。
5. **渠道状态**：点开站点的 Channel Status / 监控页，看它实际调用的端点与渲染内容，和 `status.url` 配置对照——**别信老端点还活着**（sub2api 新版把 `/api/v1/channel-monitors` 留成空壳，页面走 `/api/v1/channel-monitor-v2/models`，2026-10-12 2btocken 实证）。看页面还能量出对的语义：成功率是 0-1 小数还是百分数、首字耗时在哪个字段、无流量模型怎么标。
